# RallyMirror Studio

The complete RallyMirror website, analysis API, worker and deployment setup live
in this folder. The project uses React, TypeScript and Three.js with the team's
Python inference modules. No other frontend folder is needed.

## Open the website

From the RallyMirror project folder:

```powershell
cd frontend
npm ci
npm run dev
```

Open **http://127.0.0.1:5187/**. Node 24 is the tested version. Vite also
supports Node 20.19+ and 22.12+.

The seven recorded example views, playback controls and two-clip comparison
work without an analysis server. Each example uses actual predictions from the
same four-second rally: court, player tracking, body pose, racket, shuttle,
play phases, and a combined video. The example is a demonstration, not an
independent evaluation. Model hashes and coverage are in each run report;
`public/media/demo-provenance.json` records the source and exported video hashes.

## Run the full application

Start Docker Desktop, then from `frontend`:

```powershell
python scripts/fetch-models.py
docker compose -f deployment/compose.yaml up --build -d
```

Open **http://127.0.0.1:8000/**. This serves the built website and API from one
origin. The separate CPU worker processes uploaded rallies. The download
helper verifies the six selected model files and leaves matching files alone.

The upload form offers **Combined**, **Court detection**, **Player tracking**,
**Body pose**, **Racket detection**, **Shuttle tracking** and **Play phases**.
Individual modes execute their required dependencies; phase analysis needs
pose, racket, court and shuttle context. Uploads run inference and do not train
or modify any model. CPU inference takes longer than playback; the interface
polls stage progress while the worker runs.

Stop the application while retaining jobs:

```powershell
docker compose -f deployment/compose.yaml down
```

See [DEPLOYMENT.md](DEPLOYMENT.md) for configuration, a native Python setup,
access keys, public HTTPS hosting and the optional cloud-worker contract.
The Compose configuration binds to this computer by default; publishing to a
public domain requires a host and HTTPS configuration.

For frontend development, Vite proxies `/api` and `/healthz` to port 8000. To use
another API, set `RALLYMIRROR_API_URL` before `npm run dev`. Keep server secrets
out of `VITE_*` variables. The upload form's optional team key stays in memory.

## Folder layout

```text
frontend/
  src/               React pages, components, API client and visual styles
  public/            Fonts, licences and seven real analysis examples
  backend/
    src/             Team inference modules, analysis modes, API and worker
    configs/         Model manifest and shared feature configuration
    models/          Selected weights, fetched explicitly and ignored by Git
    tests/           API, mode, storage and model-fetch tests
  deployment/        Docker images, Compose and environment examples
  scripts/           Model preparation, example export and performance checks
  tests/             Browser tests and their media fixture
  .work/             Ignored reference clones, audit files and build scratch
  .runtime/          Ignored local runtime caches
  dist/              Ignored production website, generated by npm run build
```

The previous `court_module/outputs/frontend_build` work files have been moved
to `.work/`. Reference clones, temporary environments, models, raw training
videos, caches and generated job files are excluded from the frontend's Git
changes. Small intentional demo videos and posters are included.

The backend runtime is a pinned copy of the team's integrated modules from
`origin/main` commit `017a366aed9ec4091881b678412e14e2eca518f8`, extended here
with seven analysis modes, persisted mode selection and mode-specific rendering.
The existing root modules and current Git branch were preserved.

## Review tools

- Slow playback, frame stepping, video download and run reports.
- Visible missing-module warnings, prediction coverage and stage timings.
- Up to 20 private job links saved in this browser, including the analysis mode.
- Signed result-link refresh and bounded recovery after media failures.
- Two local videos with linked playback and an adjustable timing offset.
- Project/module explanations and evaluation evidence with dataset scope.

Overlays are baked into each MP4. Changing an example's mode selects a separately
rendered view of the same predictions. Fresh uploads run the selected mode.
There is no simulated scoring, physical shuttle-speed claim or automatic
cross-camera ghost alignment.

## Visual sources

- **ThreeUI:** renderer lifecycle, pointer interpolation and surface treatments.
- **Lunar Rover 3D Scroll:** native, section-scoped court/orbit/shuttle camera.
- **Blue Design Studio:** staged text and section entrances.
- **Aren Vale Composer:** spatial project gallery with a list alternative.

The visuals use badminton geometry and project media. Rendering is lazy-loaded,
pixel ratio and draw frequency are capped, and motion pauses offscreen or in
hidden tabs. The motion toggle and operating-system preference disable the
scroll sequence. Mobile uses normal stacked layouts. Attribution and licence
texts are in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Checks and example generation

```powershell
npm run build
npm test
# Keep the development server running in another terminal:
npm run test:e2e
```

Browser tests use installed Microsoft Edge. `npm run check:performance` checks
a production preview on port 4173. Backend tests run from `backend` with the
backend's environment: `python -m pytest tests -q`.

To rebuild the seven examples from a short raw 1280x720 clip, use the worker's
Python environment and FFmpeg on PATH:

```powershell
python scripts/build-examples.py path/to/raw-rally.mp4 --device cpu
```

This runs all six models once, then exports the focused views from those same
artifacts. See [QA.md](QA.md) for actual verification results and their scope.
